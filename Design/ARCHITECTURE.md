# Architecture — current-state map

Read PROJECT.md first. This is *what exists now*; DECISIONS.md is *why*.

One project/assembly (`src/MonoPrimitives.csproj` → `MonoPrimitives.dll`). `Core/`, `2D/`, `3D/` under `src/` are organization only — what matters is the namespace (`MonoPrimitives`/`MonoPrimitives.Primitives2D`/`MonoPrimitives.Primitives3D`, all nested under the one root namespace).

## `src/Core/` — namespace `MonoPrimitives`

Shared foundation used by both 2D and 3D — nothing here is 2D- or 3D-specific.

| File | Purpose |
|---|---|
| `Easing.cs` | 0→1 tween curves — every family (Quad/Cubic/Quart/Quint/Expo/Sine/Circ/Back/Bounce/Elastic) has In/Out/InOut, 31 functions total. Verified against the canonical easings.net/Penner formulas; full regression coverage in `tests/MonoPrimitives.Tests/EasingTests.cs`. |
| `Palette.cs` | 21 curated flat colors + `Background`, `All`/`Primary` arrays, `Cycle(index)`. Plus `GradientPairs`: inner/outer color pairs for a glossy radial-gradient "juicy ball" look via `FillCircleGradient` — a different flavor from the flat colors, not exhaustive, add more pairs as needed. |
| `ColorUtil.cs` | Hex ↔ `Color`, HSV ↔ `Color`, `Lighten`/`Darken`/`Saturate`/`Desaturate`/`Complementary`/`Invert`/`Contrast`, `Lerp`, `LerpHSV` (hue-wheel-aware). Hue is a turn in [0,1), not degrees. Plus blend modes `Multiply`/`Screen`/`Overlay`/`Additive` (pure `Color x Color -> Color`, alpha always taken from the first argument — blend color, not transparency; not a GPU blend-state operation). All of the above have permanent regression tests in `tests/MonoPrimitives.Tests/ColorUtilTests.cs`, not just ad-hoc verification. |
| `Noise.cs` | Seedable Perlin noise: `Sample1D`/`2D`/`3D` + `Fbm1D`/`2D`/`3D` + `RidgeNoise2D`/`3D` + `Turbulence2D`/`3D` (all three fBm families share one `Octaves`/`Lacunarity`/`Gain` set of instance properties, editable or set at construction — same "tunable knobs as properties" shape as `Camera2D.MoveSpeed`/`PrimitiveInput.DoubleClickTime`, not repeated per call). `Sample2D`/`3D` share one implementation (2D is a z=0 slice); `Sample1D` has its own dedicated gradient (a naive y=0,z=0 slice would degenerate — see DECISIONS.md). Core algorithm verified line-by-line against Ken Perlin's own reference implementation. |
| `RandomUtil.cs` | Seedable float-based distribution sampling: `NextUniform`/`NextInt`/`NextBool`/`NextGaussian`/`NextLogNormal`/`NextExponential`/`NextPoisson`/`NextBinomial`/`NextOnUnitCircle`/`NextInsideUnitCircle`/`NextOnUnitSphere`/`NextInsideUnitSphere`/`NextWeightedIndex`. Not thread-safe (one `Random` stream per instance, same assumption as `Noise`/`PrimitiveInput`/the cameras) — parallelize by giving each thread its own instance. `RandomUtil.Shared` is a static, genuinely thread-safe mirror of the same API built on `Random.Shared`, no seed, for when reproducibility isn't needed. `UnderlyingRandom` exposes the wrapped `Random` instance directly, for anything not covered above without desyncing into a separate stream. See DECISIONS.md for the algorithm choices (Marsaglia polar for Gaussian, Poisson/Binomial's bounded-cost approximation regimes) and `Guide/RandomUtil_Guide.md`. |
| `PrimitiveInput.cs` | Keyboard/mouse/gamepad polling, `GetAxis`/`GetVector2`, mouse drag/double-click/hit-test. `Update(GameTime)` once per frame. `DragDelta`/`IsDragging` still read correctly on the exact frame a drag ends; `IsMouseButtonDoubleClicked` checks both `DoubleClickTime` and `DoubleClickDistance`. Gamepad: `LeftStick`/`RightStick`/`LeftTrigger`/`RightTrigger` each have a `*Deadzoned` counterpart (radial, rescaled — `ApplyDeadzone` is `public static`), `SetVibration` (2- and 4-motor overloads, a stateless passthrough — no built-in duration/timer, that's a per-game call), `IsAnyButtonPressed`/`IsAnyKeyPressed`/`IsAnyMouseButtonPressed`. `IDisposable`: an optional `PrimitiveInput(GameWindow)` constructor subscribes to `TextInput`, enabling `GetCharPressed()` (a bounded 64-char ring buffer) for real typed text — the parameterless constructor leaves it always `'\0'`. `CapsLock`/`NumLock` and `SetCursor(MouseCursor)` round out the surface (plain MonoGame passthroughs that had never been wrapped). `GetWASD`/`GetArrowKeys`/`GetInputDirection` (sums WASD + arrows + deadzoned stick + D-pad, all normalized to Y-down) round out the composite helpers. `CurrentKeyboardState`/`PreviousKeyboardState`, `CurrentMouseState`/`PreviousMouseState`, `GetCurrentGamePadState`/`GetPreviousGamePadState` expose the raw polled state directly (same "escape hatch" shape as `RandomUtil.UnderlyingRandom`) for anything this class doesn't wrap. See `Guide/PrimitiveInput_Guide.md` and DECISIONS.md's Input section. |
| `FontGlyphs5x7.cs` | Raw 5×7 glyph bitmap data + layout math for the debug font. No rendering (2D and 3D each draw it differently). `WrapText(text, maxWidth, pixelSize, glyphSpacing)` greedy word-wraps (hard-breaks a too-long single word, preserves existing `'\n'` as independent forced breaks) — what `DrawString`/`DrawString3D`'s own `maxWidth` parameter calls internally (see DECISIONS.md). Full regression coverage in `tests/MonoPrimitives.Tests/FontGlyphs5x7Tests.cs` (row-span consistency per letter class, the `h` crossbar fix, fallback glyph, `MeasureText`, `WrapText`) — see `Guide/DebugFont5x7_Guide.md`. |
| `Vector2Extensions.cs` | Extension methods on MonoGame's own `Vector2`: `Angle`/`AngleTo`/`AngleToSigned`, `Rotated` (named to avoid colliding with `Vector2`'s own mutating `Rotate`/`RotateAround` — see DECISIONS.md), `PerpendicularClockwise`/`PerpendicularCounterClockwise`, `DirectionTo`/`SafeNormalize`, `Approach` (`Vector2` and `float` overloads), `ClampMagnitude`. Also `GameTimeExtensions.GetElapsedTimeSeconds()`. Full regression coverage in `tests/MonoPrimitives.Tests/Vector2ExtensionsTests.cs` — see `Guide/Vector2Extensions_Guide.md`. |
| `FastTexture.cs` | `Texture2D`/`RenderTarget2D` wrapper: raw `glTexSubImage2D` upload (~2.5-2.7x faster than `SetData` per real frame at 2500x2500, DesktopGL), falling back to `SetData` transparently when the fast path can't be established. Desktop GL only; check `IsRawUploadAvailable`/`Diagnostics`. Full/sub-rectangle/pointer `Update` overloads. See DECISIONS.md for the benchmark-methodology story behind this, and `Guide/FastTexture_Guide.md`. |
| `FrameLimiter.cs` | Paces the loop to a target FPS more precisely than `Game.IsFixedTimeStep`'s own timer — sleeps most of the remaining frame, busy-spins the last ~2ms for precision. Disables `IsFixedTimeStep` and vsync at construction (reads the `GraphicsDeviceManager` already registered as a service — construct this after it). `BeginFrame()`/`EndFrame()` bracket a frame; `TargetFps` is a live, editable property; `Elapsed` reads the internal `Stopwatch` live, mid-frame, read-only. See DECISIONS.md for the measured Sleep-jitter tradeoff this design accepts, and `Guide/FrameLimiter_Guide.md`. |
| `RectangleF.cs` | Float-precision counterpart to MonoGame's integer-only `Rectangle` — mirrors its member shape (`Left`/`Right`/`Top`/`Bottom`/`Center`/`Contains`/`Intersects`/`Inflate`/`Intersect`/`Union`), plus `FromCenter`, an implicit `Rectangle`→`RectangleF` conversion (exact), and `ToRectangle()` (rounds). Full regression coverage in `tests/MonoPrimitives.Tests/RectangleFTests.cs`. |
| `FpsCounter.cs` | Rolling-average FPS over the last `SampleCount` frames (ring buffer of frame times, `AverageFps` = frames/total-time, not an average of per-frame instantaneous FPS values). Also exposes `AverageFrameTimeMs`/`CurrentFrameTimeMs` — the same underlying average read before the fps reciprocal, more precise for comparing against a fixed frame budget since fps compresses the low end of the scale and expands the high end. `Update(GameTime)` once per frame; `CurrentFps`/`CurrentFrameTimeMs` read just the latest sample. Measurement only — draws nothing itself. Full regression coverage in `tests/MonoPrimitives.Tests/FpsCounterTests.cs`. |
| `ScreenshotUtil.cs` | `Capture(device, filePath)` — saves the current back buffer to a `.png`/`.jpg`/`.jpeg` file (format inferred from the extension, anything else throws). MonoGame's own `Texture2D.SaveAsPng`/`SaveAsJpeg` only save a texture you already own; this is the missing "get the actual on-screen frame into one" step. Full regression coverage in `tests/MonoPrimitives.Tests/ScreenshotUtilTests.cs` (round-trips a real captured frame back through `Texture2D.FromStream` and checks the pixels). |
| `ObjectPool.cs` | `ObjectPool<T>` (`T : class`) — `Get()`/`Return(item)`, optional `onGet`/`onReturn` reset hooks, `initialCapacity`, `maxSize` (past which a `Return` just drops the instance instead of growing forever). `CountActive`/`CountInactive`/`CountAll`. Doesn't track double-`Return`/never-`Get`-ted misuse — trusts the caller, same boundary as the rest of this library. Full regression coverage in `tests/MonoPrimitives.Tests/ObjectPoolTests.cs` — see `Guide/ObjectPool_Guide.md`. |
| `RingBuffer.cs` | `RingBuffer<T>` — the same fixed-capacity ring buffer `Trail2D`/`Trail3D`/`FpsCounter` each already implement privately, generalized and made public. `Add`/`Clear`/indexer (`0`=oldest)/`Newest`/`Oldest`, `IEnumerable<T>` via a custom struct `Enumerator` (allocation-free `foreach` against the concrete type, same trick `List<T>` uses). Full regression coverage in `tests/MonoPrimitives.Tests/RingBufferTests.cs` — see `Guide/RingBuffer_Guide.md`. |
| `Cooldown.cs` | A countdown `struct` (not a class — cheap enough to be a field on hundreds of simulation entities): `Update(deltaSeconds \| GameTime)`, `IsReady`/`Remaining`/`Progress`, `TryUse()` (check-and-restart in one call), `Reset()`/`ResetReady()`. Starts already `IsReady` at construction. Full regression coverage in `tests/MonoPrimitives.Tests/CooldownTests.cs` — see `Guide/Cooldown_Guide.md`. |

## `src/2D/` — namespace `MonoPrimitives.Primitives2D`

| File | Purpose |
|---|---|
| `Primitives2D.cs` | `Primitive2DBatch` — all shape drawing. Every shape family (Triangle/Rectangle/Circle/Ellipse/Poly/Polygon/Capsule/CircleSector/Ring) has the full Fill/Border/Draw × Rounded/Chamfer × Gradient/GradientRounded × Shadow/ShadowRounded matrix (built out incrementally — the non-obvious spots are in DECISIONS.md's "2D shape rendering" section). Capsule and equilateral Triangle each have both an endpoint/vertex form and a `center, size, rotation` form. Also: the outline/fillet engine, points/lines/splines (Linear/CatmullRom/Basis/BezierCubic/BezierQuadratic — Basis and BezierQuadratic expose `join`/`cap`/`jointRadius`, CatmullRom/BezierCubic are Miter-only), `DrawArrow`/`DrawGrid`/`DrawAxis`/`ClearLetterboxed`. `IDisposable`, same `_disposed`/`ThrowIfDisposed()` guard as `Primitive3DBatch`. `Effect` exposes the internally-constructed `BasicEffect` read-only for parameters this batch's own API doesn't cover. Large; grep, don't read linearly. |
| `Camera2D.cs` | Transform matrix, screen↔world, bounds/padding, smooth-follow/zoom. Two-tier update: `Update` (no input, just decays shake/settles easing — for a camera you drive yourself) and `UpdateWithInput(PrimitiveInput, float/GameTime)` (W/A/S/D pan, left-drag pan — rotation-compensated, so it still tracks the cursor under a rotated camera — wheel zoom, `R` to `Reset()`, read from a `PrimitiveInput` instance the caller owns and updates — a prototyping convenience, not baked into `Update`; doesn't call `PrimitiveInput.Update` itself). Same shape as `Camera3D`, including `Reset()` (restores construction-time Target/Offset/Rotation/Zoom, clears follow/zoom/shake state). No parameterless constructor — use `CreateDefault()` for a placeholder. Trauma-based screen shake (`AddTrauma`, baked into `GetTransformMatrix`) — see DECISIONS.md. Optionally takes a `ViewportAdapter2D` at construction (MonoGame.Extended's `OrthographicCamera(ViewportAdapter)` shape) — when set, `ScreenToWorld`/`WorldToScreen`/`GetVisibleWorldBounds`/`UpdateWithInput`'s mouse-drag pan all account for it automatically instead of assuming raw device pixels. `Offset` then live-tracks the adapter's virtual center (re-read every access, not a construction-time snapshot the way MonoGame.Extended's own `Origin` is) until assigned directly, which pins it — see DECISIONS.md. |
| `ViewportAdapter2D.cs` (+ `Boxing`/`Scaling`/`Default`/`Window` variants) | MonoGame.Extended-parity viewport adapter family: `BoxingViewportAdapter2D` (letterbox/pillarbox, uniform scale), `ScalingViewportAdapter2D` (stretch to fill, non-uniform scale), `DefaultViewportAdapter2D` (1:1, tracks device viewport), `WindowViewportAdapter2D` (1:1, tracks `GameWindow.ClientBounds`). All expose the same `GetScaleMatrix()`/`PointToVirtual`/`VirtualToPoint` surface — compose with `Camera2D` the same way regardless of which one's in use. `BoxingViewportAdapter2D` takes an optional `pixelPerfect` constructor flag: floors the fit-scale to a whole number (min 1) instead of a continuous fit, for pixel art (a fractional scale draws some source pixels wider than others) — see DECISIONS.md for why a continuous scale alone wasn't enough despite this class's own doc comment already naming pixel art as its use case. Also usable by 3D via `Primitive3DBatch.Begin(camera, viewportAdapter)`. See `Guide/Camera2D_Guide.md`. |
| `Collision2D.cs` | Overlap tests + 3 raycasts. Detection only. Includes convex-polygon overlaps (`PolyPoly`/`RecPoly`/`RecTriangle`/`TriangleTriangle`, SAT-based — require convex input) and circle/capsule-vs-any-simple-polygon (`CirclePoly`/`CircleTriangle`/`CapsulePoly`/`CapsuleRec`/`CapsuleTriangle`, NOT SAT — correct for concave polygons too, same generality as `CheckCollisionPointPoly`). `CheckCollisionCircleCapsule`/`CheckCollisionCapsuleCapsule` cover Capsule vs Circle/Capsule — the latter via a private `SegmentSegmentDistanceSquared` closest-point-between-segments core (Ericson's standard algorithm), also reused by the `Capsule*Poly` family. Full regression coverage (including a concave L-shaped polygon fixture) in `tests/MonoPrimitives.Tests/Collision2DTests.cs` — see `Guide/Collision2D_Guide.md`. |
| `DebugFont5x7.cs` | `DrawString`/`MeasureText` on `Primitive2DBatch`, via `FillRectangle`. |
| `Trail2D.cs` | Fixed-capacity fading position history. `fadeToAlpha` is clamped to [0,1]. See `Guide/Trail2D_Guide.md`. |
| `UnitCircleLut.cs` | Public precomputed unit-circle table — the 2D counterpart to the 3D library's `TrigLut`, for your own curved geometry. `Primitive2DBatch` uses it internally instead of keeping a private duplicate. `Sample` floors before casting to an index (not a raw truncating `(int)` cast), so negative/out-of-`[0,1)` input wraps exactly instead of within a curvature-sized error. `SampleRadians`/`SampleDegrees` wrap `Sample` for callers already holding an angle in one of those units, via a precomputed `TurnsPerRadian`/`TurnsPerDegree` multiply instead of a per-call divide. See `Guide/UnitCircleLut_Guide.md`. |

## `src/3D/` — namespace `MonoPrimitives.Primitives3D`

| File | Purpose |
|---|---|
| `Primitive3DBatch.cs` | Core batch: `Begin`/`End`/`Flush`, opt-in flat shading, `BuildBasis` (orthonormal basis), `ResolveSegments` (auto-LOD). `Begin(camera)` applies `camera.ViewportAdapter` automatically (letterboxes the 3D projection into its boxed rectangle) when the camera was constructed with one — no separate viewport-taking overload. `Effect` exposes the internally-constructed `BasicEffect` read-only (same escape-hatch shape as `RandomUtil.UnderlyingRandom`) for parameters this batch's own API doesn't cover. |
| `Primitive3DBatchShapes.cs` | Cube/Sphere/Cylinder/Capsule/Torus/Heightmap/Plane/Grid/`DrawAxis`/splines/`DrawArrow`/`BorderFrustum`. Every shape is `Fill`/`Border`/`Draw` overloads of one name (no `Ex`/`V`-suffixed siblings — a two-endpoint cylinder, a vector-size cube, etc. are just another overload; confirmed this is already a strict superset of every raylib `rmodels.h` 3D shape function, each one already unified this way). `DrawGridXY/XZ/YZ` draw the grid only (`showMajorLines: bool = true` toggles the every-5th-line emphasis; `lineThickness: float <= 0` (default) keeps the cheap fixed-1px `DrawLine3DFast` path, a positive value switches to scalable `DrawLine3D` for both minor and major); `DrawAxis` is separate (same `thickness <= 0` sentinel convention). Splines match 2D's family completely: `DrawSplineCatmullRom3D`/`BezierCubic3D`/`BezierQuadratic3D`/`Basis3D` plus static `GetSplinePoint*3D` sampling functions for all four. `DrawLineStrip3D` draws a properly joined camera-facing strip (miters adjacent segments' offsets at each shared interior vertex, same shape as 2D's `ComputeMiterOffset` one dimension higher) — a `Color` overload and a per-segment-`Color` overload (`Trail3D.Draw`'s own fade uses the latter). Large; grep, don't read linearly. |
| `Camera3D.cs` | View/projection, multiple modes, bounds/padding/follow/zoom. Same two-tier update as `Camera2D`: `Update` (no input — shake decay/easing only) and `UpdateWithInput(PrimitiveInput, float/GameTime)` (W/A/S/D + Space/Ctrl move, Q/E yaw, Z/X roll, right-drag look, wheel zoom, read from a caller-owned `PrimitiveInput`). Camera + controller merged into one class. Movement/rotation/sensitivity speeds are editable properties (`MoveSpeed`, `RotationSpeed`, etc.), not constants. Trauma-based screen shake (`AddTrauma`, baked into `GetViewMatrix`, offset along the camera's own right/up axes) — see DECISIONS.md. Optionally takes a `ViewportAdapter2D` at construction, same as `Camera2D` — `GetWorldToScreen`/`GetScreenToWorld`/`GetScreenToWorldRay` then resolve it automatically instead of requiring an explicit `Viewport` argument. `Reset()` restores the construction-time pose (Position/Target/Up/Fovy/Projection/near/far) and clears zoom/follow/head-bob/shake state, including `Trauma`, matching `Camera2D.Reset()`; bound to `R` by default in `UpdateWithInput`. Movement/rotation methods verified formula-by-formula against raylib's `rcamera.h`. Full regression coverage in `tests/MonoPrimitives.Tests/Camera3DTests.cs` — see `Guide/Camera3D_Guide.md`. |
| `Collision3D.cs` | Wraps `BoundingSphere`/`BoundingBox`/`Ray`, plus capsule support (overlap + raycast, including `CheckCollisionCapsuleBox`), plane/triangle/quad raycasts (`GetRayCollisionPlane`/`Triangle`/`Quad`, the last two confirmed against raylib's own `GetRayCollisionTriangle`/`Quad`). Full regression coverage in `tests/MonoPrimitives.Tests/Collision3DTests.cs` — see `Guide/Collision3D_Guide.md`. |
| `TrigLut.cs` | Precomputed sin/cos table for per-vertex trig — public, the 3D counterpart to 2D's `UnitCircleLut`. `SinIndex`/`CosIndex` (raw table index) and `SinCosStep(step, steps, ...)` (division of a circle, used internally to build rings/slices) are the geometry-building entry points; `Sample(t01, ...)`/`SampleRadians`/`SampleDegrees` are the continuous-angle entry points matching `UnitCircleLut.Sample`'s shape for a caller's own curved geometry. `SinCosStep`'s generic (non-exact-division) path floors before splitting into index+fraction, same fix as `UnitCircleLut.Sample`'s — negative `step` used to pick the wrong pair of adjacent table entries otherwise. See DECISIONS.md and `Guide/TrigLut_Guide.md`. |
| `Trail3D.cs` | 3D counterpart to `Trail2D`. `thickness` defaults to `Primitive3DBatch.DefaultLineThickness` (sentinel ≤0), `fadeToAlpha` is clamped to [0,1]. `Draw` renders via `Primitive3DBatch.DrawLineStrip3D`'s per-segment-color overload (one joined strip, no gap at a bend) using two reusable scratch buffers sized once at construction — no per-frame allocation. See `Guide/Trail2D_Guide.md`. |
| `DebugFont5x7.cs` | `DrawString3D`/`MeasureText3D`/`GetBillboardAxes` — billboarded text (cylindrical facing) by default; an overload taking an explicit `right`/`up` basis opts out of billboarding for text that should hold a fixed orientation. Never lit. `GetBillboardAxes`'s right/up verified (algebraically and by test) to exactly match the camera's own rendered view-space X/Y axes when it looks at the labeled position, from any side. Full regression coverage in `tests/MonoPrimitives.Tests/DebugFont3DTests.cs` — see `Guide/DebugFont5x7_Guide.md`. |
| `Vector3Extensions.cs` | Extension methods on MonoGame's own `Vector3`: `AngleTo` (unsigned, `[0,PI]`), `AngleToSigned(other, axis)` (signed, right-hand rule around an explicit axis — 3D has no default rotation plane the way 2D does), `Rotated(axis, radians)` (wraps `Quaternion.CreateFromAxisAngle` + `Transform`), `DirectionTo`/`SafeNormalize`, `Approach` (`Vector3` overload only — the `float` overload deliberately stays on `Vector2Extensions`, which is already dimension-agnostic; duplicating it here would make any call site with both namespaces in scope ambiguous, `CS0121`), `ClampMagnitude`. Deliberately doesn't wrap `Vector3.Reflect`/`Clamp`/`Lerp` (confirmed already native by inspecting the referenced assembly) or add a bare `Angle()` (still no single canonical "heading" in 3D without naming a plane). Lives in `Primitives3D`, not `Core/`, since nothing in this library's 2D half ever touches a `Vector3`. Full regression coverage in `tests/MonoPrimitives.Tests/Vector3ExtensionsTests.cs` (including a 200-random-case cross-check that `Rotated(a.Flatten(), AngleToSigned(a,b,axis))` lands on `b`'s own flattened direction — the first version of that check rotated the un-flattened vector instead and looked like a bug in the source; it was the test comparing the wrong vectors, see DECISIONS.md) — see `Guide/Vector2Extensions_Guide.md`'s "3D: Vector3Extensions" section. |

## `samples/MonoPrimitives.Sample/`

Minimal runnable MonoGame game referencing `MonoPrimitives`, plus `MonoGame.Extended` (sample-only). Proves the package works end-to-end; not a real game. Tab toggles between two visual-regression galleries — `Gallery2D.cs` (2D, camera-controlled) and `Gallery3D.cs` (3D, free-fly camera) — both the same row-per-shape-family/cell-per-Fill-Border-Draw-variant/text-caption structure, so a change to either library can be eyeballed the same way.

## `templates/PrimitiveBase/`

A `dotnet new` template (shortname `primitivebase`, `dotnet new install ./templates/PrimitiveBase` then `dotnet new primitivebase -n YourGame`; the scaffolded project's own namespace is whatever `-n` name you pick, not `PrimitiveBase` — that's just this source template's own internal name): mgdesktopgl-based scaffold at 1080p virtual resolution via `BoxingViewportAdapter2D` (letterboxed) + `Camera2D` (`Offset = Vector2.Zero`, so world (0,0) is the screen's top-left, not center — the one non-obvious setting, see DECISIONS.md), MSAA x4, `PrimitiveInput(Window)` (the `GameWindow`-aware constructor, so `GetCharPressed()` works out of the box), a `RenderContext` record struct (`GraphicsDevice`/`Graphics`/`SpriteBatch`/`Batch2D` — deliberately just those 4, declared directly in `Game1.cs` rather than its own file), 60 FPS via vanilla `IsFixedTimeStep = true` (independent of the new `FrameLimiter` class — this template intentionally doesn't use it), and `ClearLetterboxed` + a centered gradient circle to prove it renders. References the published `MonoPrimitives` NuGet package (pinned to an exact version, not a `ProjectReference`), bumped by hand each time a new version should be picked up — deliberately outside `MonoPrimitives.slnx` for that reason, built as its own CI job instead (see `Design/README.md`). Its own code was verified against a local build via a temporary `ProjectReference` swap before each new version was published.

## `examples/`

Small standalone MonoGame apps (each its own `.csproj` referencing `MonoPrimitives.csproj` directly, not the sample) demonstrating library usage beyond the gallery. `examples/test/` holds one visual test per non-primitive-drawing component (`ViewportTest/` — every `ViewportAdapter2D` mode, 2D and 3D, verified via a `ScreenToWorld(WorldToScreen(x))` round-trip plus a rendered-marker-position check; `NoiseTest/` — `Noise`'s 1D/2D/3D samples, keys 1-3: an Fbm1D terrain silhouette, an Fbm2D heightmap terrain via `FillHeightmap`, and a live `Sample3D` field with Z as time; `ParticleTrailTest/` — several `Trail2D`s with different capacity/thickness/fade styles, dragged behind particles that bounce off the window edges and each other (`Collision2D` detects the overlap, the test itself resolves it — the library stops at detection by design); `TextReadabilityTest/` — every printable glyph `DebugFont5x7` supports plus a pangram at reading size, pannable/zoomable via `Camera2D`; `CollisionTest/` — every `Collision2D` overlap/ray check, keys 1-6, two controllable points (one mouse, one W/A/S/D, swappable with Space) reinterpreted per mode as circle/rect/line/triangle/polygon/ray, red on overlap; `InputPanelTest/` — a full `PrimitiveInput` state panel: a lit-up keyboard layout, mouse position/buttons/scroll/drag, and a gamepad panel with a graceful "not connected" fallback — this rounds out the non-primitive-drawing component coverage `examples/test/` set out to have). `examples/demos/` holds small non-menu/non-pause playable demos built directly on `PrimitiveInput` (not a camera's `UpdateWithInput` convenience) to prove the library at "real game" scale: `Breakout/` — paddle/ball/bricks, `BoxingViewportAdapter2D` letterboxing a portrait playfield, `Camera2D` used passively for a screen-shake hit on every brick break; `Tetris/` — the 7 standard pieces (rotation states as small cell-offset tables), line clears, no camera needed at all; `Asteroids2D/` — thrust/rotate/fire, splitting asteroids, screen wrap, colorful on purpose (not the original's monochrome vectors); the camera is hand-driven from ship speed — `FollowTarget` for a lag-behind feel, `Camera2D.SmoothDamp` easing `Zoom` out while thrusting — both called directly by the demo's own update, not `UpdateWithInput`; `Asteroids3D/` — the same idea in a wrapped cube of space: yaw/pitch + thrust flight always relative to world Up for predictable turning (Q/E roll is a cosmetic camera bank only, never fed back into flight — see DECISIONS.md), `Camera3D.FollowTarget` driving a lag-behind chase cam, also colorful; `Platformer2D/` — run/jump/stomp across geometric platforms and enemies (circles/rectangles, no sprites), exercising separate-axis AABB collision resolution, `Camera2D.FollowTarget` + `TargetBounds` clamping, and shake-on-hit together; `Snake/` — classic grid movement/growth/self-collision, no camera needed; `Boids/` — a Craig Reynolds flocking simulation (games AND simulations are both in scope) with mouse attract/scatter, using a wrap-aware toroidal distance for neighbor checks (see DECISIONS.md).

## `tests/MonoPrimitives.Tests/`

A headless `Game` (`TestRunnerGame`), not an xUnit project — see DECISIONS.md for why. `Collision2DTests`/`Collision3DTests`/`NoiseTests`/`ColorUtilTests` are pure-math, no device needed; `ShapeTests3D` (one call per public 3D shape method, asserting real geometry got emitted) and `LightingRegressionTests` (renders an offscreen lit sphere and reads pixels back) need the real `GraphicsDevice` a running `Game` provides. `ScreenshotUtilTests` also needs the device (it captures/reads back the real back buffer, not an offscreen target). `ShapeTests2D` is the 2D counterpart, and stricter — every major shape family (Fill/Border/Draw) renders to an offscreen target and gets its actual pixels sampled (a known-interior point is the fill color, a known-exterior point stays background, Border-only leaves the center unfilled), not just "did it throw." `PolygonInsetRegressionTests` and `ClearLetterboxedTests` are permanent regressions for two real 2D bugs (see DECISIONS.md) — 2D previously had zero automated protection against a shape rendering in the wrong place/size, unlike 3D's smoke tests and join-gap regressions. `Primitive2DBatchLifecycleTests` checks `Begin()` throws `ObjectDisposedException` after `Dispose()`, and that `Dispose()` is idempotent. `PrimitiveInputDeadzoneTests` covers `ApplyDeadzone`'s pure math directly (no device needed). `BoxingViewportAdapter2DPixelPerfectTests` covers the `pixelPerfect` option's scale-flooring math against the test runner's own real backbuffer size, plus a full render-through-a-camera check. Run the built exe directly (0 = all passed, 1 = a failure) — not through a test runner; CI does this on every push/PR via `xvfb-run` (see `Design/README.md`). `Vector2Benchmark.cs` (informational only, like `FastTexture`'s own benchmark) times MonoGame's `Vector2` against `System.Numerics.Vector2` — see DECISIONS.md for the result.

## Machinery worth knowing before you touch nearby code

- `ComputeJoint`/`BuildRoundedCornerBoundary` (2D) — shared fillet engine behind every rounded corner. See DECISIONS.md for its per-corner clamp caveat.
- `FillPolygonGradientByNearestVertex` (2D) — colors a rounded boundary's many points by nearest original vertex (a rounded corner's arc has no 1:1 vertex mapping).
- Blend state is `NonPremultiplied` in both batches — see DECISIONS.md.
- `PushQuadLit`/`PushTriangleLit` (3D) — face normal comes from vertex winding order; get it backwards and lighting/culling breaks silently. See DECISIONS.md.
- `UnitCircleLut` (2D) / `TrigLut` (3D) — precomputed trig tables, both public. Use these for new curved geometry, not raw `MathF.Sin`/`Cos`.
